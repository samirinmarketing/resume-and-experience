Eventin 4.0 Release Campaign

The full content loop for a major WordPress plugin release: launch blog, version comparison, QA report, readme rewrite, 62 annotated screenshots, and a founder post. All inside eight weeks.

The Problem 01 / 04

Eventin 4.0 was a ground-up rebuild: the plugin moved from a classic WordPress metabox UI to a React-based wizard interface. This wasn't a feature update; it was a generation change. Every piece of documentation, every screenshot in the readme, every comparison with the previous version needed to be created from scratch.

The marketing challenge was twofold. Existing users needed to understand what changed and why it was worth updating (without feeling their workflow was being disrupted). New users needed to see a modern plugin that competed visually with newer entrants, not a legacy tool with a fresh version number.

Strategy 02 / 04

Treated the 4.0 release as a full campaign rather than a single launch post:

  • Launch blog: "Eventin 4.0 is Here." Structured as a feature walkthrough, not a changelog dump, leading with the user-facing improvements.
  • v3 vs. v4 comparison: A direct before-and-after document showing the old metabox UI alongside the new React wizard. This became the internal reference for support and the external reference for hesitant upgraders.
  • QA report: Documented known issues and their resolution status, establishing transparency with the user base rather than pretending 4.0 was flawless on day one.
  • 62 annotated screenshots: Captured across 28 May to 6 Jun, covering the full admin interface. These served both the readme and the documentation site.

Execution 03 / 04

  • "Eventin 4.0 is Here" launch blog, emphasising the React UI rebuild and new template wizard.
  • v3 vs. v4 comparison document with side-by-side UI references spanning both plugin generations.
  • QA report documenting known issues for the dev team and support team.
  • Complete readme.txt rewrite for wordpress.org, structured for plugin search ranking.
  • 62 admin screenshots across three capture groups (sequential UI walkthrough, tagged captures, and code-optimisation visuals).
  • Founder post (first draft) for the CEO to publish under their name, announcing the release with a personal narrative.
  • Release email copy for the existing user base.
